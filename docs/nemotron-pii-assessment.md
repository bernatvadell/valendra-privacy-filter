# NVIDIA Nemotron-PII dataset assessment

Assessment date: 2026-11-05. This source has been prepared for a separate experiment; it is **not** part of the current training run.

## Provenance and licensing

- [GLiNER-PII model card](https://huggingface.co/nvidia/gliner-PII) identifies [NVIDIA Nemotron-PII](https://huggingface.co/datasets/nvidia/Nemotron-PII) as its training dataset. The GLiNER model and the dataset have different licenses: the model uses the NVIDIA Open Model License, while the dataset declares **CC BY 4.0** and requires NVIDIA attribution.
- Dataset revision inspected: `b70ffaf5ff39e079776134c5bf4381f00a9fd1ed`. Records are synthetic English text generated by NVIDIA's NeMo Data Designer. Using the published data would not require running a teacher model or calling a data-generation API in this project.
- The dataset card says 100,000 records split 50,000/50,000. At the inspected revision, the [Hugging Face dataset viewer size endpoint](https://datasets-server.huggingface.co/size?dataset=nvidia%2FNemotron-PII) reported **100,000 train and 100,000 test rows**. Recheck source metadata before preparing the dataset.
- `locale` distinguishes `us` and `intl`, not text language. The dataset is documented as English and does not substitute for Spanish or Spain-specific evaluation.

## Annotation compatibility

The published rows have `text` and `spans`, but the viewer exposes `spans` as a **string containing a Python literal**, not a native list or JSON. A loader must use bounded safe parsing, validate field types and check every original character offset against the corresponding text. Some annotation `text` values are numeric; compare their explicit string representation only when it matches the original slice exactly. Quarantine mismatches rather than guessing offsets.

An exploratory structural audit inspected 300 train and 300 test documents: 100 rows each at offsets 0, 50,000 and 99,000 in each split. The sample is deterministic, not random or representative of the full dataset.

| Split | Documents | Annotated spans | Offset/value mismatches | Documents with mismatches | Numeric annotation values |
| --- | ---: | ---: | ---: | ---: | ---: |
| Train | 300 | 2,074 | 8 | 5 | 21 |
| Test | 300 | 2,057 | 17 | 16 | 25 |

These figures check structural agreement only; they do not establish whether the remaining labels are semantically correct. An earlier rough count also flagged numeric values as mismatches; the table above distinguishes these from actual disagreements after explicit conversion.

Useful source categories include `date_of_birth`, `api_key`, `password`, `account_number`, `bank_routing_number`, `credit_debit_card`, `first_name`, `last_name`, `email`, `phone_number`, `street_address`, `ipv4`, `ipv6`, and `url`. Define an explicit mapping and annotate unsupported or ambiguous categories as ignored. In particular, do not infer date of birth from generic `date`; company names and other categories outside the project taxonomy must follow an explicit negative/ignore policy. Check the provenance and treatment of all synthetic credential-like values before adding them.

## Full preparation and isolation snapshot

The pinned source was processed against a checksum-verified snapshot of the existing baseline. The source files contained 100,000 records per split. Preparation retained **72,772 NVIDIA train**, **7,730 NVIDIA validation** and **95,920 NVIDIA test** documents. It quarantined 4,081 source-train and 4,073 source-test records with offset/value mismatches; source-train records were also excluded for 14,510 identity-value overlaps with the reserved NVIDIA test, 898 identity overlaps between newly assigned train/validation, four template overlaps with NVIDIA test and four baseline identity overlaps. Seven NVIDIA test records overlapped baseline identity values. One additional exact duplicate was removed. Counts and source-label distributions are recorded in the NVIDIA manifest.

During mixed-dataset preparation the baseline contained 28,511 distinct normalized high-signal values appearing across its splits and two canonical templates appearing across splits. These are repeated synthetic strings, **not proof of repeated real individuals**; nevertheless, they can make evaluation optimistic. The mixed copy retains the baseline training side, conservatively excludes lower-priority held-out documents sharing those values, and excludes the four documents linked to cross-split template groups. It adds a separately generated English/Spanish address challenge after excluding 18 examples that shared a specific address with another source.

The resulting `data/processed-openpii-nemotron-v1` snapshot has **268,298 train**, **33,151 validation**, **22,262 baseline test** and **14,461 challenge** documents. Validation includes 1,022 explicitly labeled `DATE_OF_BIRTH` spans; challenge includes 1,982 address spans. The independently stored NVIDIA test has 95,920 documents and is not included in the mixed dataset. A post-write audit found zero cross-split exact texts, canonical templates, source groups or tracked identity values and zero overlaps of those kinds with the NVIDIA holdout.

The configured seed-selected 2,048-window validation subset contains supervised examples from all ten categories, including 51 windows containing `DATE_OF_BIRTH`. Separate saved audits checked raw spans, BIOES transitions, offsets and reconstructed entity boundaries for all 343,260 mixed windows and all 186,772 NVIDIA windows without detected structural errors. Aggregate reports are under `experiments/` and bind to the respective dataset-manifest SHA-256 hashes.

The high-signal policy hashes annotated email, phone, government ID, financial ID and secret values of at least eight normalized characters, plus address values of at least 15 characters containing a digit. IDs are compared within their mapped category. These fingerprints never leave process memory. The policy can reject common fictional constants and does not prove separation of shared names, short IDs, unannotated PII, all address forms, underlying synthetic personas or semantic paraphrases. No model performance on this new dataset is claimed.

## Research protocol

1. Preserve the current Qwen3 checkpoint and dataset manifest. The current run continues on the original dataset; its validation may be optimistic because repeated values were found across the original splits.
2. Train on the mixed copy only in a new, identifiable experiment. Keep the NVIDIA test split independent for final evaluation and retain separate Spanish evaluation.
3. Do not use the NVIDIA test for model selection, alter the active run's input data, or present synthetic-only metrics as real-world generalization.
